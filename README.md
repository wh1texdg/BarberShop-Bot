# Барбершоп Bot

Backend-система онлайн-бронирования с Telegram-интерфейсом: клиенты записываются
к мастеру на услугу через диалог с ботом, администратор управляет услугами,
мастерами и расписанием прямо в Telegram. Данные хранятся в PostgreSQL,
миграции — через Alembic, всё поднимается одной командой `docker compose up`.

## Возможности

**Клиент**
- запись: услуга → мастер → дата → свободное время → контакты → подтверждение
- вариант «Любой мастер» с поиском первого мастера, у которого реально есть слот
- повторная проверка выбранного времени перед подтверждением
- просмотр и отмена своих записей с ограничением по времени
- история визитов и отзывы 1–5 с комментарием
- уведомления: о создании записи, за сутки, за 2 часа, об отмене

**Администратор** (доступ по Telegram ID из `.env`)
- просмотр расписания на сегодня и ближайшие 14 дней
- отмена записей и перевод визита в `completed` / `no_show`
- автоматический запрос отзыва после завершённого визита
- управление мастерами и услугами (создание, деактивация, назначение услуг мастерам)
- управление расписанием: недельные рабочие часы, перерыв, выходные, разовые
  исключения (отгул / индивидуальные часы на конкретную дату)
- поиск по клиентской базе
- статистика за последние 30 дней и список последних отзывов
- уведомление о каждой новой записи

## Стек

Python 3.12, aiogram 3, SQLAlchemy 2 (async), PostgreSQL, Alembic,
pydantic-settings, APScheduler (напоминания), Docker Compose, pytest.

## Запуск

```bash
git clone <repo>
cd barbershop-bot
cp .env.example .env
# заполните BOT_TOKEN и ADMIN_IDS в .env
docker compose up -d
```

Миграции применяются автоматически при старте контейнера `bot`
(`alembic upgrade head` перед запуском бота).

Чтобы сразу иметь тестовые услуги и мастеров, можно один раз выполнить:

```bash
docker compose exec bot python -m scripts.seed
```

## Переменные окружения (`.env`)

| Переменная | Назначение |
|---|---|
| `BOT_TOKEN` | токен бота от @BotFather |
| `DATABASE_URL` | строка подключения к PostgreSQL (async, `postgresql+asyncpg://...`) |
| `ADMIN_IDS` | Telegram ID администраторов через запятую |
| `CANCEL_MIN_HOURS_BEFORE` | за сколько часов до начала запрещена отмена клиентом (по умолчанию 2) |
| `TIMEZONE` | часовой пояс для расписания и напоминаний |
| `SLOT_STEP_MINUTES` | шаг сетки свободного времени (по умолчанию 30 мин) |

## Архитектура

```text
Telegram
   ↓
aiogram (handlers: start / booking / admin)
   ↓
Service Layer (booking_service, schedule_service, notification_service)
   ↓
Repository (user, catalog, appointment, schedule)
   ↓
PostgreSQL (SQLAlchemy 2 async + Alembic)
```

Логика не размазана по хэндлерам: проверка свободного времени и создание
записи живут в `app/services/`, хэндлеры в `app/bot/handlers/` только
управляют диалогом и вызывают сервисы.

### Защита от двойной записи

При подтверждении записи хэндлер вызывает `BookingService.create_appointment`,
которая внутри одной транзакции:
1. блокирует (`SELECT ... FOR UPDATE`) все активные записи мастера на эту дату;
2. повторно проверяет, что слот всё ещё свободен (рабочие часы, перерыв,
   пересечения с другими записями);
3. только после этого создаёт запись и коммитит.

Если два клиента одновременно подтверждают один и тот же слот, вторая
транзакция дожидается коммита первой и получает `SlotUnavailableError` —
клиенту показывается «Похоже, этот слот только что заняли».

## Тесты

```bash
pip install -r requirements-dev.txt
pytest
```

Покрыты: расчёт свободных слотов (рабочие часы, перерыв, выходные, разовые
исключения, прошедшие даты), запрет двойной записи, пересечение записей
(в т.ч. кейс из ТЗ: запись 15:00–16:30 блокирует 16:00, но не блокирует 16:30),
запрет отмены за услугами.

## Админ-команды

Кнопки «Мастера» / «Услуги (админ)» показывают список и подсказки. Полный
набор команд:

```text
/add_master                      — добавить мастера (диалог)
/remove_master <id>              — деактивировать мастера
/assign_service <master_id> <service_id>

/add_service                     — добавить услугу (диалог)
/set_price <id> <цена>
/remove_service <id>             — деактивировать услугу

/set_schedule <master_id> <день 0-6, Пн=0> <начало HH:MM> <конец HH:MM> [перерыв_с] [перерыв_до]
/set_dayoff <master_id> <день 0-6>
/add_exception <master_id> <YYYY-MM-DD> dayoff
/add_exception <master_id> <YYYY-MM-DD> <начало HH:MM> <конец HH:MM>
```

## Что пока не входит

Лист ожидания, промокоды, онлайн-оплата, временная блокировка слота на 5 минут
и мультифилиальность сознательно оставлены следующим этапом. Текущая
архитектура уже разделяет Telegram-обработчики, сервисы и репозитории, поэтому
эти функции можно добавлять без переноса основной бизнес-логики в handlers.
